# Day5 · 要点同意（重要操作先等人点头）

> 今天目标：让助手做一件**会改数据**的事，并在 Runtime 里**点同意或驳回**。  
> 这是「AI 乱来」的刹车。半小时左右。

角色：**EHS 工程师（可写）**。

---

## 步骤

1. 先到 **Domain 台账** 看一眼：挑一条**还没闭环、且没有未关闭整改单**的隐患，记住它的编号（界面上能看见的那个 id）。  
2. 打开 **Agent**，输入类似：  
   `给隐患 <编号> 开整改单：现场复查并更换过期器材`  
   （把编号换成你的。）  
3. 发送后看步骤：若系统开启了「写操作要审批」，任务可能会停在**等你点头**。  
4. 打开 **Runtime** 页：  
   - 找到状态像 **awaiting_approval / 需先审批** 的那条；  
   - 点进去，在「待审批」里选 **同意** 或 **驳回**。  
5. 同意后再回 Domain：应能看到新开的整改单（或对应变化）。  
6. 若你点了驳回：台账不应被偷偷改掉——这就是刹车的意义。

不同环境提示文案可能略有差别，**意思对上就行**：先停住 → 人点头 → 再继续。

---

> **今天带走的一句话：**  
> 真改数据前，可以先让人点「同意」——AI 不能一个人说了算。

---

## 卡住了怎么办

- 直接开单成功、没出现审批 → 到 Runtime 看 HITL 开关是否打开；或再试一次明确的「开整改单」说法。  
- 一直停在待审批 → 你还没在 Runtime 点同意/驳回。  
- 找不到编号 → Day1 先开一条隐患相关数据，或用列表里现成的。
