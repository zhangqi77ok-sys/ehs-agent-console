## 0. 你在学什么（一句话）

做一个 **EHS 隐患整改** 的小系统：人可以在网页上改台账；AI Agent 也可以改——但 **改数据必须走同一套规则**（状态机、权限、审计）。  
面试官关心的不是「会调 ChatGPT」，而是：**出事了能不能追责、能不能续跑、能不能拦错误写入**。

建议路径（别跳）：

1. 先会点 **领域台账**（没 Agent）  
2. 再开 **Agent** 看步骤  
3. 再玩 **Runtime**（暂停、审批、Trace）  
4. （七天后再说）练习页 + 面试备用文件夹

启动：

```bash
# 后端
cd backend && source .venv/bin/activate   # Windows: .venv\Scripts\Activate.ps1
LLM_PROVIDER=mock uvicorn app.main:app --reload --port 8000

# 前端
cd frontend && npm run dev
# 浏览器打开 http://127.0.0.1:5173
```

## 2. 知识点速查（先懂词）

| 词 | 人话 | 在本项目里 |
|----|------|------------|
| 领域层 | 真正的业务规则 | 隐患/整改单状态机、`capa.py` |
| Agent 循环 | 模型决定调哪个工具，拿到结果再继续 | `app/agent/loop.py` |

| HITL | 敏感操作先等人点头 | 开单前「待审批」 |

| RAG | 先检索制度文档再回答 | `search_regulations` |
| Memory 压缩 | 聊天太长时摘要旧内容 | Ch10 session |

## 3. 痛点（为什么要做，不是为了炫技）

工业里最常见的「疼」——每个都对应本仓一个设计：

| 痛点（现场会怎样） | 没有它时 | 本仓怎么落地 |
|--------------------|----------|--------------|
| 假闭环：没证据也点「已完成」 | 出事追责对不上 | 关单必须 `evidence_note` |
| Agent 乱开单、乱改状态 | 脏数据进库 | 工具走状态机；写操作可 HITL |
| 一次请求做不完就丢了 | 长任务白跑 | checkpoint 暂停/续跑 |
| 出了 bug 说不清模型调了啥 | 无法复盘 | Trace / Replay / request_id |
| 聊天越来越长又贵又慢 | 超时、超预算 | 上下文压缩 |
| 只会 Chat，不会权限 | 通不过安全评审 | 角色 ACL + 审计 + JWT |
| 「我本地能跑」交付不了 | 上线翻车 | Compose + Postgres 路径 |
| 改完不知道变好没 | 回归靠感觉 | mock 多维 Eval 门禁 |
| 一个 Agent 又查又写太乱 | 职责不清 | Supervisor 分角色（可并行） |
| 答制度靠瞎编 | 合规风险 | RAG 检索带分数的原文块 |

**面试怎么说痛点**：先说现场会怎样坏，再说你拦在哪一层——比背名词加分。

## 5. 每章「一句话 + 痛点 + 落地点」（全覆盖）

### Ch1 领域台账
- **一句话**：先让业务规则硬，再让 Agent 碰数据。  
- **痛点**：假闭环、乱改状态、说不清谁改的。  
- **落地点**：状态机 + 证据关单 + 角色权限 + 审计表 + 可点 UI。

### Ch2 Agent 循环
- **一句话**：模型只负责选工具；改数据仍走领域层。  
- **痛点**：Agent 直写数据库绕过规则。  
- **落地点**：手写 loop；工具封装领域 API。

### Ch3 SSE
- **一句话**：步骤边跑边推到界面，人能看见 Agent 在干嘛。  
- **痛点**：黑盒、只能等最终答案。  
- **落地点**：SSE 推 steps/budget；可演练超时。

### Ch4 Durable run
- **一句话**：跑到一半能停，还能接着跑。  
- **痛点**：长任务中断全丢。  
- **落地点**：`agent_runs` checkpoint / resume。

### Ch5 Trace + HITL
- **一句话**：敏感写入先审批；事后能回放每一步。  
- **痛点**：误开单不可逆；故障无法复盘。  
- **落地点**：pending 审批；spans + replay。

### Ch6 Eval + Compose
- **一句话**：没真密钥也能自动回归；一键起 Postgres。  
- **痛点**：改代码不知是否变差；只会本机 SQLite。  
- **落地点**：mock eval；docker-compose。

### Ch7 面试材料
- **一句话**：把项目翻译成面试官能听懂的故事。  
- **痛点**：有代码不会讲。  
- **落地点**：interview / resume / oral 文档。

### Ch8 JWT + 日志
- **一句话**：用令牌证明身份；每笔请求有 request_id。  
- **痛点**：只靠请求头演示，不像生产。  
- **落地点**：JWT/API Key；访问日志。

### Ch9 RAG
- **一句话**：答制度先查文档块，再说话。  
- **痛点**：模型瞎编法规。  
- **落地点**：切块 + 向量检索工具。

### Ch10 Memory
- **一句话**：历史太长就摘要，别把窗口撑爆。  
- **痛点**：长会话贵、慢、丢重点。  
- **落地点**：session 压缩（有测试）。

### Ch11 多 Agent
- **一句话**：查的人、开单的人分开，主管分活。  
- **痛点**：一个角色又查又写难控权。  
- **落地点**：Investigator / Clerk + 工具白名单。

### Ch12 就业包
- **一句话**：Demo 剧本、JD 对照、题库打包。  
- **痛点**：作品散、演示临场乱。  
- **落地点**：demo-script、jd-gap-matrix、mock-interview。

### Ch13–22（加固）
- **一句话**：往生产 JD 再靠：指标、pgvector、MCP 薄层、多维评测、练习页、OTLP、JWKS、并行 Agent。  
- **痛点**：面试官问「生产怎么观测/鉴权/并行」。  
- **落地点**：见各 ch13+ 课记；上限见 `./面试备用/readiness-scorecard.md`。

## 6. 学起来轻松的三个习惯

1. **先点后读**：先在页面上制造一次「失败」（无证据关单、viewer 去写），再读课记——痛点就记住了。  
2. **每章只记三句**：一句话、一个痛点、一个落地点（上表已写好）。  
3. **周末只刷题**：Practice 页 + `./面试备用/mock-interview.md`，不会的回对应章课记，别从头通读。
