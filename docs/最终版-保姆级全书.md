# 最终版 · 保姆级全书（一次看完）

> 写给你：容易看懵、三分热度、希望有人一步步带着点。  
> **这篇是完整版。** 可以从头滚到尾；也可以只挑某一章练。没有「今天必须停」的门槛。  
> 语气：大白话。不背面试词，不谈 JD。

## 开场：这软件是什么（30 秒）

把它想成一个**工厂安全整改小控制台**：

- 网页上管**隐患**（发现的问题）和**整改单**（怎么修的任务单）
- 旁边有个 **AI 助手**，也能查、也能帮开单
- 但**改数据必须遵守同一套规矩**——关单要证据、访客写不了、真改之前可以先让人点同意

三个页签记住就够：

| 页签 | 人话 |
|------|------|
| **Domain 台账** | 人点按钮改的数据（隐患、整改单） |
| **Agent** | 跟 AI 助手说话的地方 |
| **Runtime** | 看任务跑到哪、要不要你点同意 |

你要亲手摸一遍的，是：**怎样做出一个敢上线的小系统**——不是背黑话。

## 第 0 章 · 装环境（让网页能打开）

**目标：** 浏览器里看见这个项目的页面。

把项目想成两个人在干活：

- **后端** = 厨房（管数据、规矩）
- **前端** = 点餐屏（你看见的网页）

两边都要开着，网页才有东西吃。

### Windows · PowerShell（两个窗口，别关）

#### 窗口 A · 后端

```powershell
cd <你的仓库路径>\ehs-agent-console\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:LLM_PROVIDER="mock"
uvicorn app.main:app --reload --port 8000
```

看到类似 `Uvicorn running on http://127.0.0.1:8000` 就对了。

#### 窗口 B · 前端

```powershell
cd <你的仓库路径>\ehs-agent-console\frontend
npm install
npm run dev
```

浏览器打开：**http://127.0.0.1:5173**

你应该看到顶栏有：**Domain 台账 / Agent / Runtime**，还有「租户」「角色」下拉框。

#### Mac / Linux（对照）

激活改成 `source .venv/bin/activate`，环境变量写在同一行：

```bash
LLM_PROVIDER=mock uvicorn app.main:app --reload --port 8000
```

前端同样：`npm install` → `npm run dev`。

> **带走的一句话：**  
> 后端管规矩，前端管画面；两个窗口都开着，才能点。

### 卡住了怎么办

- 报错说端口被占用 → 关掉以前开过的终端，或换一台电脑先试。
- `Activate.ps1` 被禁止 → 用「以管理员打开」或换用 `cmd` 里 `.venv\Scripts\activate.bat`。
- 页面空白 / 连不上 → 先看窗口 A 还在不在跑；把**完整报错原文**复制出来问人。

**自检：□ 我能打开 http://127.0.0.1:5173**

## 第 1 章 · 关单必须有证据

**目标：** 亲手走完一张整改单——空着证据关不了，写了才能关。大约 20～30 分钟。

先记住画面：

- **隐患** = 发现的问题（比如灭火器过期）
- **整改单** = 怎么修的任务单

### 步骤

1. 确认网页已开（不会开 → 先回第 0 章）。
2. 顶栏点 **Domain 台账**。
3. 角色选 **EHS 工程师（可写）**，租户保持 **default**。
4. 左边列表点一条隐患（比如灭火器相关的）。
5. 右边「开整改单」框里写措施，例如：`更换过期灭火器并点检`，点 **开整改单**。
6. 下面「整改单时间线」出现新单，状态大概是 **待执行**。
7. 按按钮顺序点（跟升级一样）：
   - **开始执行** → 变成「执行中」
   - **提交验收** → 变成「待验收」
   - **关闭（需证据）** → 弹出「填写验收证据」
8. **先故意把框留空**：看「确认关闭」是不是灰的、点不了。
9. **再写一句** `已更换并拍照点检`，点 **确认关闭**。
10. 整改单关掉，隐患应变成 **已闭环**。

> **带走的一句话：**  
> 没有验收说明，系统不准你假装修好。

### 卡住了怎么办

- 看不到「开整改单」→ 角色是不是还停在 viewer？改成工程师再刷新试。
- 已经有未关闭的单 → 先把旧单推完，或换另一条隐患。
- 关了但隐患没变「已闭环」→ 把时间线里的状态截图/原文发出来。

**自检：□ 我空证据关不了，写了才能关**

## 第 2 章 · 访客写不了

**目标：** 换成「只能看」的人，感受**不是谁都能改**。半小时内。

### 步骤

1. 顶栏角色改成 **viewer（只读）**。
2. 仍在 **Domain 台账**，点一条还没闭环的隐患。
3. 看右边：应该出现提示，大意是 **viewer 只读，无开单按钮**——没有「开整改单」。
4. 若这条下面已有整改单，时间线上的「开始执行 / 提交验收 / 关闭」按钮也应没有。
5. （可选）页面下方 **审计** 点「展开」：能看见谁做了什么；有的操作会记成 denied（拒绝）。
6. 玩完后，把角色改回 **EHS 工程师（可写）**，别忘了，后面要用。

> **带走的一句话：**  
> 不是谁都能改；改了还要留下痕迹。

### 卡住了怎么办

- 还能开单 → 确认下拉框真的是 viewer，必要时刷新页面。
- 看不到审计 → 滚到页面最下面，「审计」卡片里点「展开」。
- 列表是空的 → 用工程师角色先按第 1 章造一条数据，再切回 viewer。

**自检：□ viewer 开不了单**

## 第 3 章 · 第一次开 Agent

**目标：** 让 AI 助手答一句，并**看见它一步步干活**，不是只吐一段话。半小时。

角色先改回 **EHS 工程师（可写）**。

### 步骤

1. 顶栏点 **Agent**。
2. 输入框写：`有哪些未闭环隐患？`
3. 点发送。
4. **盯右边（或下方）的步骤列表**：会一条条出现——想做什么、调了什么工具、工具回了什么。
5. 左边会出现助手的回答。你对照一下：它说的隐患，和 Domain 台账里是否对得上。
6. （可选）再问一句：`查制度：灭火器`——若有资料，它会先搜再答。

这一章**不要**急着让它开整改单；开单涉及「先同意」那一套，放到第 5 章。

> **带走的一句话：**  
> AI 是操作员；真正的规矩还在台账那一套。

### 卡住了怎么办

- 一直转圈没步骤 → 看后端窗口还在不在；报错原文贴出来。
- 回答很空 → 先用第 1 章造几条未闭环隐患，再问。
- 英文报错看不懂 → 整段复制即可，不用自己翻译。

**自检：□ 我看见过至少一轮「调工具」的步骤**

## 第 4 章 · 看步骤（人话版）

**目标：** 再跑一轮 Agent，**把右边每一步用自己的话念出来**。不背名词。半小时。

### 步骤

1. 打开 **Agent** 页，再问一次：`有哪些未闭环隐患？`（或换个问题：`隐患 HZ-xxx 是什么状态？`——把 xxx 换成你列表里真有的编号）。
2. 步骤刷出来后，对着屏幕用嘴说三遍（可以小声）：
   - 「这一步是它在**决定**要不要动手」
   - 「这一步是它**伸手去查/改**」
   - 「这一步是**手里拿到的结果**」
3. 注意：步骤是**一条条冒出来**的，不是等全部做完才突然整屏出现——这样你才知道它卡在哪。
4. （可选）打开 **Runtime** 页瞄一眼：这里以后能看「暂停 / 续跑 / 审批」；今天只需知道「跑过的任务会留在这儿」。

> **带走的一句话：**  
> 步骤一条条推过来，是为了让你看见它卡在哪，而不是傻等。

### 卡住了怎么办

- 步骤闪一下就没了 → 再发一次同样的问题；或到 Runtime 里点开最近一条看详情。
- 完全看不懂英文工具名 → 没关系，只记「查」还是「改」两种。
- 页面卡死 → 刷新；两个终端窗口还在就行。

**自检：□ 我能用自己的话解释一串步骤**

## 第 5 章 · 要点同意（重要操作先等人点头）

**目标：** 让助手做一件**会改数据**的事，并在 Runtime 里**点同意或驳回**。这是「AI 乱来」的刹车。半小时左右。

角色：**EHS 工程师（可写）**。

### 步骤

1. 先到 **Domain 台账** 看一眼：挑一条**还没闭环、且没有未关闭整改单**的隐患，记住它的编号（界面上能看见的那个 id）。
2. 打开 **Agent**，输入类似：  
   `给隐患 <编号> 开整改单：现场复查并更换过期器材`  
   （把编号换成你的。）
3. 发送后看步骤：若系统开启了「写操作要审批」，任务可能会停在**等你点头**。
4. 打开 **Runtime** 页：
   - 找到状态像 **awaiting_approval / 需先审批** 的那条；
   - 点进去，在「待审批」里选 **同意** 或 **驳回**。
5. 同意后再回 Domain：应能看到新开的整改单（或对应变化）。
6. 若你点了驳回：台账不应被偷偷改掉——这就是刹车的意义。

不同环境提示文案可能略有差别，**意思对上就行**：先停住 → 人点头 → 再继续。

> **带走的一句话：**  
> 真改数据前，可以先让人点「同意」——AI 不能一个人说了算。

### 卡住了怎么办

- 直接开单成功、没出现审批 → 到 Runtime 看 HITL 开关是否打开；或再试一次明确的「开整改单」说法。
- 一直停在待审批 → 你还没在 Runtime 点同意/驳回。
- 找不到编号 → 第 1 章先开一条隐患相关数据，或用列表里现成的。

**自检：□ 我在 Runtime 里点过一次同意或驳回**

## 第 6 章 · 查制度（先搜再答）

**目标：** 问一个**要查资料**的问题，看它是不是先搜再答。轻松一章。

### 步骤

1. 打开 **Agent**。
2. 输入：`查制度：灭火器`（或 `灭火器点检有什么要求？`）。
3. 发送，盯步骤：应出现类似「搜法规 / 查制度」的工具调用，再给出回答。
4. 看回答里有没有提到资料来源或片段——有，就说明它不是纯瞎编。
5. （可选）故意问一个仓库里**不太可能有**的冷门问题，体会：资料不够时它会怎样（含糊、或说找不到）。

> **带走的一句话：**  
> 先查资料再回答，比张口就编更靠谱。

### 卡住了怎么办

- 没有任何「搜索」步骤 → 换用带「查制度」三字的问法再试一次。
- 回答像通用常识、没贴资料 → 正常现象之一；重点是你有没有看见「先搜」。
- 报错 → 把后端窗口最后几行复制出来。

**自检：□ 我看见过一次「先搜再答」**

## 第 7 章 · 你能对外说的三句话

**目标：** **不看文档**，用自己的嘴说清你摸过什么。对着镜子或录音说一遍就行。

### 步骤

1. 合上（或切走）本仓库文档。
2. 大声说下面三句（允许用你自己的措辞，意思对即可）：

**第一句 · 规矩**  
「我做了一个隐患整改小控制台：关单必须写验收说明，否则关不了。」

**第二句 · 权限**  
「访客只能看，工程师才能改；改动会进审计。」

**第三句 · 助手**  
「旁边有个 AI 助手，步骤能看见；真要改数据时，可以先让人点同意；查制度时会先搜资料。」

3. 说完后，打开网页随便点开 Domain / Agent / Runtime，指着屏幕把三句再对一遍——能指到，就算真会了。
4. 若某一句指空了：回到对应章节补做（第 1 / 2 / 3～6 章），别硬背。

> **带走的一句话：**  
> 能指着屏幕讲清楚，比背一百个名词有用。

### 卡住了怎么办

- 三句说不全 → 打开对应章节看「带走的一句话」，用那句顶上。
- 紧张、说不利索 → 先写在纸上再念，不算作弊。
- 想继续深挖 → 去 `docs/lessons/` 当词典查，**不要**一上来啃面试夹。

**自检：□ 三句话能指着屏幕说完**

## 附录 A · 黑话对照（全书小词典）

碰到陌生词，先来这儿对一下人话。不必背。

| 词 | 人话 |
|----|------|
| 后端 / API | 厨房：存数据、检查规矩 |
| 前端 | 你点的网页 |
| venv | 给这个项目专用的 Python 小房间 |
| mock | 假装有 AI，不花钱、结果稳定，方便练习 |
| 隐患 | 发现的问题 |
| 整改单 | 怎么修的任务单 |
| 闭环 | 问题从发现到修好、验收完，整条链走完 |
| 假闭环 | 没证据也点「修好了」——现场最疼的一种作假 |
| 验收证据 / evidence | 关单时必须写的说明（照片编号、谁复核等） |
| 角色 / ACL | 你是工程师还是访客，决定能不能写 |
| 租户 | 数据隔离的「公司隔间」；练习先用 default |
| 审计 | 事后清单：谁、什么时候、做了什么、成没成 |
| Agent | 会按步骤调用工具的 AI 助手 |
| 工具 / Tool | AI 的手：查清单、开单…… |
| Agent 循环 | 想一想 → 动手 → 看结果 → 再想 |
| SSE | 服务器一点点把步骤推到网页（所以你会看见「在刷」） |
| budget | 还剩多少步/配额，防止它死循环 |
| Trace | 事后回放：当时调了啥（Runtime 里） |
| HITL | Human in the loop：关键步骤插进「人来点头」 |
| 待审批 / awaiting_approval | 任务暂停，等你同意或驳回 |
| 写操作 | 会改数据库的动作（开单、关单…），比「只查询」更危险 |
| RAG | 先检索再生成：有依据再说话 |
| embedding / 切块 | 把长文档切成小段再编号，方便搜（先不用深究） |
| 领域台账 / Domain | 人点按钮改的数据那一页 |
| Runtime | 看任务、审批、回放的那一页 |
| 课记 lessons | 详细说明书；全书摸完再用 |
