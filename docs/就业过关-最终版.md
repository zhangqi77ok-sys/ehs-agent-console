## 开场：对标什么岗、能证明什么

**对标：** 成都一带常见的 **AI Agent 应用 / Agent 后端**（约 20–30k RMB 口径）。JD 里常出现：手写或可控的 Agent 循环、工具不乱写库、人工审批（HITL）、流式输出、可暂停续跑、评测门禁、RAG、多租户权限、可观测。

**这个仓库能证明的：**

- 你不是只会调一个聊天框——有**领域规矩**（关单要证据、访客写不了、审计可查）
- 上面挂的是**自己写的 Agent 循环**（不是黑盒框架一包到底），工具走同一套规矩
- 能**当场点给人看**：台账 → 助手 → 运行时审批 / 暂停 / 回放
- 有**自动化测试**（含 mock 评测）和 **Compose/Postgres** 生产形状

**这个仓库不能保证的：**

- **不能保证录用 / offer**——口语、和对方业务是否对口、对手盘、系统面/行为面，仓库包不了
- 没有完整企业 SSO（真 IdP）、没有真连 Tempo 那种全链路追踪、没有金标线上评测灰度

一句话收口：**技术追问可以指到代码和页面；录用还要靠你讲清楚、对上他们的业务。**

## 口头常问（8～12 题 · 大白话短答）

练习：闭卷说，再说完对照。答案都基于**本项目**。

**1. 这项目到底是啥？**  
工厂安全整改小控制台：网页管隐患和整改单，旁边有 AI 助手；改数据都过同一套规矩（证据、权限、审计）。

**2. 为啥先做台账再做 AI？**  
业务最怕「假装修好」。台账规矩不过关，AI 只会加速造假。所以先把关单、权限、审计做硬，再挂助手。

**3. 关单为啥必须写验收说明？**  
状态机规定：关闭要非空证据。空的直接拒绝，并留下审计。人和 AI 都不能绕。

**4. 访客为啥开不了单？**  
只读角色写操作会被拒（常见是 403），并记「被拒」。换工程师才能写。

**5. 你的 AI 和 ChatGPT 套壳有啥区别？**  
有领域状态机和审计；能暂停、能审批、能回放、能评测、能多租户。工具不能直接偷改库，只能走领域接口。

**6. Agent 循环怎么跑的？**  
手写：观察 → 决定 → 行动，有步数预算。mock 或真模型可切换。一步步的 steps 可以流式推到页面。

**7. 为啥写操作要人点同意？**  
读风险低；开单/关单不好撤销。所以写工具先停住，人批准才进领域改数据。

**8. 任务断了怎么办？**  
进度可存库，之后从断点续跑。流式只解决「看着爽」；落库才解决「进程挂了还能接」。

**9. 制度检索怎么做的？**  
文档切块 → 本地向量/打分 → 取最相关几段，工具带回出处和分数。本地可复现；需要时可以接到 Postgres/pgvector。

**10. 怎么证明不是偶发能跑？**  
固定评测用例 + mock，结果稳定，并且进了 pytest。真模型评测可选，不挡日常合并。

**11. 登录和排障怎么讲？**  
支持 JWT、API Key，演示也可用头。每个请求有 request_id，响应头能带回，方便对日志。

**12. 离正式上班还差啥？（主动说加分）**  
完整企业登录（真 IdP）、真全链路追踪接到公司平台、生产级向量运维与金标灰度、以及**真人模拟面试和业务对口**——仓库补不了嘴和匹配，但技术空白已经压得很低。
